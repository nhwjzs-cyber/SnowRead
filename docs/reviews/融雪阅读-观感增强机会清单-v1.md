# 融雪阅读 · 观感增强机会清单 v1

基线：0.10.2 / versionCode 16（源码包 `融雪阅读-v0.10.2-source.zip`）
范围：只讨论"状态变化时的过渡与反馈"，不改排版、不改数据、不引第三方、不加权限。
配套：`融雪阅读-观感增强-效果预览-v1.html`（可点，按同一套令牌与时长演示 8 个效果）

---

## 0. 先给结论

翻了全部 UI 代码（MainActivity 1091 行、12 个自绘控件、Motion 原语），观感缺口集中在三件事：

1. **一堆控件仍在"硬切"**：`ToggleRow` 的滑块、`ChoiceStrip` 的选中底、`SettingsSection` 的展开、书架每次重建、听书迷你条、封面到位——全部是 `setVisibility` / `invalidate` / 换 background，中间没有一帧过渡。
2. **已经写好的原语没人用**：`Motion.interpolate()`（0 处调用）正是为"自绘控件的 0..1 插值"准备的，Toggle 滑块本该用它。`Motion.enter/exit`、`capturePage()/revealPage()` 也只在少数路径上用了。
3. **两处性能问题在吃掉已有的动效**：拖动翻页时每帧 `new LinearGradient`；书架 `getView` 完全不复用（每次新建 4 个 View + 解码封面）。这两处不修，加再多特效也会被掉帧抵消。

优先级建议：P0 五项都是"半天内、只看不改逻辑"，收益最直接；P1 的章节浮层和书签吸附是新增体验；P2 属排期项。

## 2. P1：新增反馈与空间提示（1–2 天）

### 6. 拖动时不再每帧分配渐变（`PagedReaderView.java:436`）

`drawBoundary()` 每次调用都 `new LinearGradient(...)`。拖动和翻页是逐帧重绘，60fps 下每秒 60 个对象，GC 一来就是一次掉帧——这正好落在"手指正在拖"的瞬间，用户读作"卡了一下"。

改法：按（方向 × 深度）缓存两个 shader，宽度或主题变化时才重建（0.10.1 已用过这个写法）。**不改任何视觉表现，只去掉抖动。**

### 7. 翻页的纸张层次（`PagedReaderView.drawPage/drawBoundary`）

现在只有接缝处一道阴影。建议给移动中的那一页加：

- 前沿 1px 高光（`argb(20,255,255,255)` 叠在页边缘）；
- 阴影贴着移动页的边缘走（现在贴在接缝，视觉上像"缝"，不像"叠"）。

不加 3D 卷曲、不加纸张噪点——那与"安静"原则冲突，而且低端机先崩。

### 8. 章节切换浮层（`MainActivity.updateProgress()` 620-627）

`chapterLabel` 在顶部工具栏里，而工具栏大多数时候是收起的。也就是说**翻过章边界时，界面没有任何提示**。

建议：`currentTitle` 变化且在阅读页时，在 `readerStage` 上方 1/3 处淡入一枚 pill「第三章 纸上的路」，1.4s 后淡出。翻页、滚动、进度条跳转都会自然触发；同一章内不重复。

这是"我在哪"的空间提示，不是装饰，且只需一个 TextView + 两次 `Motion.to`。

### 9. 书签圆点的吸附与确认（`BookmarkSeekBar.java:22-26`）

现状：圆点是静态 2dp 实心点；手指靠近 12dp 内只记录 `candidate`，界面无变化；拖动进度条时下方只显示"跳至 37.8%"。

建议三层反馈：

1. 手指进入命中区 → 该点半径 2→3.5dp 并描一圈细环（`Motion.interpolate` 驱动，FAST）；
2. 松手跳转 → 该点 pulse 一次（`Motion.badge`）；
3. 拖动时把"跳至 x%"补成"第六章 · 27.4%"——`document.readingTitle(offset)` 现成可用。

### 10. 封面到位时淡入（`BookCoverView.java:18`）

自定义封面是异步解码后 `setBitmap()`，现在"啪"地替换掉占位色块。改成 120ms alpha 0→1（在 `onDraw` 里给 bitmap 加一层 `paint.setAlpha`），书架滚动时封面会"浮"出来而不是闪。

### 11. 拖放分类的高亮与落地（`ShelfCategoryDrag.java:62-63`）

`ACTION_DRAG_ENTERED` 里直接 `setScaleX(1.04)` + 换背景，是硬跳；`DROP` 成功后也没有任何确认，只是整页重建。

建议：进入目标 chip 用 `animate()` 120ms 放大到 1.04 并加描边；落点成功后 `Motion.badge(chip)` + 底部提示淡出"已加入 3 本"。这处是"多选拖拽归类"的主交互，反馈越确定，用户越敢用。

### 12. Aa 分组展开（`SettingsSection.java:49-52`）

`body.setVisibility(value?VISIBLE:GONE)`。这是 0.10.2 新做的六组折叠面板，展开/收起是面板里最高频的动作。

建议：`body` 高度 0↔测量值 180ms + 内容 alpha，结束置 `GONE`；箭头用两个 glyph 交叉淡入（**不旋转**，规范第 2 条）。这是"只动 alpha/translation/scale"唯一的例外，理由：单面板、高度在展开前已知、不与滚动争用，且不做就会一直是硬切。

## 4. 不建议做

| 想法 | 为什么不做 |
|---|---|
| 3D 卷页 / 仿真翻书 | 与"安静、不做装饰性动画"冲突；`StaticLayout` 逐行变形在低端机上必掉帧 |
| 纸张纹理噪点、翻页粒子、光斑 | 装饰性，且与半透明工具栏的轻量感冲突 |
| 整页视差、循环呼吸动画 | 长时间阅读会干扰专注；也是耗电项 |
| Lottie / 任何动效库 | 违反"不引第三方、不加体积"；现有 `Motion` 已够用 |
| 真正的背景模糊（工具栏） | `RenderEffect` 需 API 31+，中低端机代价高；0.10.2 的半透明底板已经达到目的 |
| 翻页音效 | 无音频资源；静音场景（夜间、地铁）反而扣分 |

## 5. 验收标准

- 每次界面状态变化都能指出"从哪来、到哪去"，不存在一帧硬切；
- 打开"减少动效"、系统动画缩放为 0、TalkBack 触摸探索时，全部直达终态（现有 `Motion.enabled()` 已覆盖，新增项必须同样先判）；
- 拖动翻页期间 `dumpsys gfxinfo` 不出现新的掉帧（#6 修完应比现在更平）；
- 不新增权限、不引第三方库，APK 增量来自纯代码（预计 < 20KB）；
- 大字号 / 横屏 / 夜读三态下，位移量与对比度不破版。
