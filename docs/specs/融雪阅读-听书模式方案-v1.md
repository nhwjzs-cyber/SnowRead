# 融雪阅读 · 听书模式方案 v1.0

适用范围：Android 0.7+（minSdk 23 / targetSdk 35）。
目标：在不引入网络、不引入第三方 TTS SDK 的前提下，用系统 TTS 做一个可靠的后台听书模式。

---

## 0. 结论与边界

### 推荐路线

**系统 TTS + 前台服务 + MediaSession + 音频焦点 + 通知。**

- 不内置神经 TTS 模型，不引入 Lottie/播放器 SDK。
- 应用本身仍然**不申请 INTERNET 权限**；系统 TTS 引擎自己决定是否联网。
- 优先选择 `Voice.isNetworkConnectionRequired() == false` 的离线语音；没有离线中文语音时明确提示。
- v1 不做多角色配音、不做音频导出、不做 Android Auto。

### 必须接受的取舍

| 项目 | 0.7 现状 | 听书模式 |
|---|---|---|
| 权限 | 0 个权限 | 需要前台服务、唤醒锁、通知权限 |
| 后台 | 无后台服务 | 必须有前台服务，否则锁屏会被杀 |
| 通知 | 无 | 锁屏/通知栏媒体控制 |
| 语音 | 无 | 依赖系统 TTS 引擎和语音包 |
| 离线 | 完全离线 | App 离线；系统 TTS 可能需联网下载语音 |

新增权限：

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK"/>
<uses-permission android:name="android.permission.WAKE_LOCK"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
```

服务声明：

```xml
<service
    android:name=".ListenService"
    android:exported="false"
    android:foregroundServiceType="mediaPlayback"
    android:stopWithTask="false"/>
```

> 注意：Android 13+ 要动态申请 `POST_NOTIFICATIONS`；Android 14+ 必须声明 `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 并在 `startForeground` 时传 `mediaPlayback` 类型。

## 2. 用户体验流程

### 首次进入

1. 点击耳机图标。
2. 检查系统 TTS：
   - 无引擎 → “未安装系统语音引擎”，按钮跳系统语音设置。
   - 有引擎但无中文 → “缺少中文语音”，按钮安装语音数据。
   - 只有联网语音 → 提示“此语音需要联网，离线可能不可用”，仍可继续。
3. 请求通知权限（Android 13+）：
   - 允许 → 正常后台听书。
   - 拒绝 → 提示“锁屏控制不可用”，可选择“仅前台听书”或去设置。
4. 从当前阅读位置开始，显示播放面板。

### 播放中

- 锁屏/通知栏：播放/暂停、上一章、下一章、停止。
- 耳机线控/蓝牙：通过 `MediaSession` 接收播放/暂停/上一首/下一首。
- 来电/导航播报：音频焦点丢失，自动暂停；恢复后按策略续播。
- 拔出耳机：`ACTION_AUDIO_BECOMING_NOISY`，立即暂停。
- 回到书架：底部迷你播放条继续显示。
- 退出阅读：服务继续，通知保留。

### 暂停/继续

- 暂停 = `TextToSpeech.stop()`，保存当前句 `start`。
- 继续 = 从当前句开头重新 `speak`。
- 因为按句/短句切分，最多重复一句，不会重复整段。

## 3. 总体架构

```text
MainActivity / Reader
        │ bind / start
        ▼
ListenService（前台服务，播放的唯一owner）
        ├── TtsEngine          TextToSpeech 初始化、voice、speak、stop
        ├── SpeechQueue        chunk 队列、当前句、下一句预取
        ├── TextChunker        纯 Java 切句、offset 映射
        ├── AudioFocus         音频焦点
        ├── MediaSession       锁屏/蓝牙/耳机控制
        ├── ListenNotification 通知栏/锁屏
        ├── WakeLock           部分唤醒锁
        ├── SleepTimer         定时停止
        └── LibraryRepository  与 Activity 共享书库/进度
```

关键原则：

1. **服务是播放的唯一 owner**，Activity 旋转、退到后台、被回收都不影响播放。
2. **Activity 只发命令、收状态**，不直接持有 `TextToSpeech`。
3. **进度只有一个写入者**：服务写听书进度；Activity 阅读时写阅读进度；通过同一个 `LibraryRepository` 串行化。
4. **TTS 回调不在主线程**，统一 post 到服务主线程再改状态。

## 4. 关键实现

### 4.1 文本切分：`TextChunker`

```java
final class SpeechChunk {
    final int start;   // 绝对字符 offset
    final int end;
    final String text;
}

final class TextChunker {
    static List<SpeechChunk> split(String text, int from, int maxChars) {
        // 1. 跳过空白
        // 2. 在 [from, from+maxChars] 内找句末：。！？!?…；; 换行
        // 3. 把后引号/后括号并入本句：”’」』）】
        // 4. 找不到句末，退到逗号/顿号
        // 5. 再找不到，硬切 maxChars，但不能切断 surrogate pair
        // 6. 返回绝对 start/end + 清理后的朗读文本
    }
}
```

约束：

- `maxChars = Math.min(2800, TextToSpeech.getMaxSpeechInputLength())`。
- 推荐每句 40–300 字；长句按逗号切，保证暂停/续听粒度。
- 朗读文本把连续空白压成一个空格；保留标点，让 TTS 自然停顿。
- `start/end` 必须能映射回 `TextDocument.text`，高亮和进度都依赖它。

### 4.2 TTS 初始化：`TtsEngine`

```java
final class TtsEngine {
    interface Callback {
        void onReady();
        void onStart(SpeechChunk chunk);
        void onRange(int start, int end); // API 26+，可能不回调
        void onDone(SpeechChunk chunk);
        void onError(int code);
    }

    void init(Context context, Locale locale);
    void speak(SpeechChunk chunk, float rate);
    void stop();
    void setVoice(Voice voice);
}
```

初始化顺序：

1. `new TextToSpeech(appContext, status -> ...)`。
2. `status == SUCCESS` 才继续；否则报“语音引擎初始化失败”。
3. `setAudioAttributes(USAGE_MEDIA / CONTENT_TYPE_SPEECH)`。
4. `setLanguage(Locale.CHINA)`；检查 `LANG_MISSING_DATA` / `LANG_NOT_SUPPORTED`。
5. `getVoices()` 过滤 `!voice.isNetworkConnectionRequired()`，优先离线。
6. `setSpeechRate(0.5–2.0)`、`setPitch(0.9–1.1)`。
7. `setOnUtteranceProgressListener(...)`。

`UtteranceProgressListener`：

- `onStart`：更新 UI“正在朗读”。
- `onRangeStart`（API 26+）：绝对 offset = `chunk.start + start`，用于词级高亮。
- `onDone`：下一句。
- `onError`：重试当前句一次；再失败进入错误态。
- `onStop`：忽略过期回调。

每个 utteranceId 带 `generation:start`，`stop/seek` 后旧回调一律丢弃。

### 4.3 播放循环：`SpeechQueue`

```text
IDLE
  └─ play(bookId, offset) → PREPARING
PREPARING
  ├─ 加载 TextDocument / 找章节 / 切句
  ├─ TTS init
  └─ 成功 → PLAYING；失败 → ERROR
PLAYING
  ├─ speak(currentChunk)
  ├─ onDone → 下一句；章末按“自动连播”决定
  ├─ pause → PAUSED
  └─ stop → IDLE
PAUSED
  ├─ resume → PLAYING（从当前句开头）
  └─ stop → IDLE
ERROR
  ├─ retry → PREPARING
  └─ stop → IDLE
```

实现要点：

- 一次只 `speak` 一个 chunk，`QUEUE_FLUSH`；不把整章塞进 `QUEUE_ADD`。
- 当前句开始后，预取下一句到内存，减少句间空隙。
- `onDone` 到章末：
  - “自动连播”开：下一章第一句；可选先读章节标题。
  - 关：暂停，显示“本章已听完”。
- 跳转/换 voice/换 speed：
  - `tts.stop()` → 重新定位到目标句 → `speak`。
  - 换 speed 可立即重读当前句，或下一句生效；推荐“当前句重读”，用户感知更直接。

### 4.4 进度同步：共享 `Book.offset`

- 听书和阅读共用 `LibraryStore.Book.offset`，默认“听读到哪，读到哪”。
- 服务每句开始/暂停/章末写一次 `offset`；不要逐词写。
- `LibraryStore.save()` 加 `synchronized`，或通过 `LibraryRepository` 单线程写。
- Activity 打开阅读页时，如果服务在播放，阅读页跳到当前 TTS offset，并可选跟随。
- 退出听书时，当前 TTS offset 就是阅读进度。

### 4.5 高亮与自动翻页

给 `PagedReaderView` 和 `ReaderAdapter` 增加独立的“听书高亮”：

```java
void setListenHighlight(int start, int end);
```

- 句级：高亮当前整句。
- 词级：`onRangeStart` 可用时只高亮当前词。
- 分页模式：如果 `follow == true` 且当前页不包含 offset，`goTo(offset)`。
- 滚动模式：`smoothScrollToPosition(rowAt(offset))`，节流 120–150ms。
- 用户手动翻页/滚动 → `follow = false`，显示“回到朗读位置”按钮；点击恢复跟随。
- 不要每收到一个词回调就 `goTo`，否则会抖动。

### 4.6 前台服务与通知

`ListenService`：

```java
public final class ListenService extends Service {
    @Override public int onStartCommand(Intent intent, int flags, int startId) {
        // 处理 ACTION_PLAY / PAUSE / NEXT / PREV / STOP
        // 首次 startForeground，必须在 5 秒内
        return START_STICKY;
    }
    @Override public IBinder onBind(Intent intent) { return binder; }
}
```

通知：

- `NotificationChannel("listen", IMPORTANCE_LOW)`，无声音、无震动。
- `Notification.MediaStyle` + `MediaSession.Token`。
- 动作：上一章、播放/暂停、下一章、停止。
- `setOnlyAlertOnce(true)`、`setOngoing(isPlaying)`。
- `setVisibility(PRIVATE)`，public version 只显示“正在听书”，避免锁屏泄露书名。
- 点击通知打开阅读页/听书面板。

Android 版本：

- API 26+：创建 channel。
- API 29+：`startForeground(id, notification, FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK)`。
- API 33+：动态申请 `POST_NOTIFICATIONS`。
- API 34+：manifest 声明 `FOREGROUND_SERVICE_MEDIA_PLAYBACK`。
- API 31+：从后台启动 FGS 可能抛 `ForegroundServiceStartNotAllowedException`，从可见 Activity 启动并 try/catch。

### 4.7 音频焦点与耳机

```java
AudioAttributes attrs = new AudioAttributes.Builder()
    .setUsage(AudioAttributes.USAGE_MEDIA)
    .setContentType(AudioAttributes.CONTENT_TYPE_SPEECH)
    .build();

AudioFocusRequest focus = new AudioFocusRequest.Builder(AudioManager.AUDIOFOCUS_GAIN)
    .setAudioAttributes(attrs)
    .setOnAudioFocusChangeListener(listener)
    .build();
```

策略：

- `AUDIOFOCUS_LOSS`：暂停，标记 `resumeOnFocus = false`。
- `AUDIOFOCUS_LOSS_TRANSIENT`：暂停，标记 `resumeOnFocus = true`。
- `AUDIOFOCUS_GAIN`：如果 `resumeOnFocus` 且不是用户主动暂停，续播。
- `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK`：TTS 没有音量 duck API，直接暂停最稳。
- 注册 `ACTION_AUDIO_BECOMING_NOISY`：耳机拔出立即暂停。

### 4.8 唤醒锁

```java
PowerManager.WakeLock wake = pm.newWakeLock(
    PowerManager.PARTIAL_WAKE_LOCK, "snowread:listen");
wake.setReferenceCounted(false);
wake.acquire();
```

- 只在 `PLAYING` 持有；`PAUSED/STOP/ERROR` 释放。
- `onDestroy` 必须释放。
- 不要持有 `FULL_WAKE_LOCK`，不要让屏幕常亮；听书应该允许熄屏。

### 4.9 睡眠定时

- 服务内 `Handler` 记录 `timerEnd`。
- 到点后不立即 `stop`，而是等当前句 `onDone` 再暂停，避免半句话被截断。
- “本章结束”模式：到章末暂停。
- 定时状态持久化；进程重建后如果已过期，恢复为暂停。
- 不做音量渐变（TTS 没有 per-utterance 音量，改系统音量会影响用户）。

### 4.10 错误与恢复

| 错误 | 处理 |
|---|---|
| 无 TTS 引擎 | 提示 + 跳系统语音设置 |
| 无中文语音 | 提示安装语音数据；允许用户选其他语言 |
| 语音需要联网 | 提示“离线可能不可用”，优先离线 voice |
| TTS 初始化超时 | 8 秒超时，提示重试 |
| `onError` | 当前句重试一次；连续失败暂停并提示 |
| 音频焦点丢失 | 暂停；按策略续播 |
| 服务被杀 | `START_STICKY`；重开恢复“暂停”态，不自动播放 |
| 通知权限拒绝 | 提示；允许仅前台听书 |
| 存储写入失败 | Toast + 保留内存进度；下次重试 |

### 4.11 权限与系统限制

- `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`、`WAKE_LOCK` 是普通权限，安装即授予。
- `POST_NOTIFICATIONS` 是运行时权限，Android 13+ 必须请求。
- 不要申请 `INTERNET`；系统 TTS 引擎自己处理网络。
- 不要申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 作为默认流程；只给引导。
- Android 14 前台服务必须从可见界面启动；播放按钮点击时启动最稳。
- 用户从最近任务划掉应用：`stopWithTask=false` 继续播放；通知提供停止。

### 4.12 UI 设计

**入口**

- 阅读页顶部栏：耳机图标，contentDescription“听书”。
- 阅读选项菜单也加“听书”，保证可发现。
- 不建议直接加第 5 个底部导航项：4 个已经占满，窄屏会挤。

**听书面板**

- 书名、章节名、当前句预览（2 行，当前句高亮）。
- 进度：本章/全书百分比，可拖动按句跳转。
- 主控制：上一句、播放/暂停、下一句。
- 次控制：上一章、下一章、停止。
- 语速 chips：0.8 / 1.0 / 1.2 / 1.5 / 2.0。
- 语音：当前 voice 名称，点击进入选择/试听。
- 定时：15/30/60 分钟、本章结束。
- 跟随朗读开关。
- 首次使用提示：“听书使用系统语音；锁屏播放需要通知权限。”

**书架迷你播放条**

- 位于书架底部、导入按钮上方。
- 显示“正在听《书名》 · 章节”，播放/暂停、停止、打开。
- 不遮挡列表最后一项；高度约 56dp。

**通知/锁屏**

- 标题：书名；副标题：章节名。
- 动作：上一章、播放/暂停、下一章、停止。
- 锁屏隐私模式隐藏书名。

- 12MB 文本、超长章节、无标点文本、英文书、混合中英文。

**验收指标**

- 点击听书到出声 < 2 秒（TTS 已初始化时 < 500ms）。
- 句间空隙 < 200ms。
- 锁屏 30 分钟不中断。
- 暂停/继续最多重复一句。
- 无 ANR、无崩溃、无内存泄漏。
- 通知/锁屏/蓝牙控制可用。
- 关闭动画/TalkBack 不影响播放。

## 5. 实施计划

| 阶段 | 内容 | 预估 |
|---|---|---|
| Phase 0：技术验证 | TTS 初始化、中文 voice、`onRangeStart` 支持度、前台服务、锁屏通知、音频焦点 | 1–2 天 |
| Phase 1：MVP | 服务、TTS、切句、播放/暂停/停止、上一句/下一句、上一章/下一章、进度、通知、音频焦点、唤醒锁、句子高亮、入口、权限 | 4–6 天 |
| Phase 2：体验完善 | 语音选择、语速、定时、迷你播放条、自动翻页、耳机拔出、错误处理、通知隐私 | 4–6 天 |
| Phase 3：打磨与测试 | 词级高亮、OEM 适配、进程恢复、设备矩阵、性能与内存 | 2–4 天 |

**总计：约 2–3 周（1 名 Android 开发）。**

### Phase 1 退出标准

- 锁屏连续播放 10 分钟。
- 通知/锁屏可播放/暂停/切章。
- 来电/耳机拔出自动暂停。
- 暂停后从当前句继续。
- 杀进程后重开恢复暂停态和进度。
- 无 TTS 引擎/无中文语音有明确引导。

## 6. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 系统 TTS 音质参差 | 听感差 | 提供 voice/engine 选择、试听、语速 |
| 没有离线中文语音 | 离线不可用 | 优先离线 voice；提示安装；后续可内置神经 TTS |
| TTS 不支持 pause | 暂停只能 stop | 短句切分，最多重复一句 |
| `onRangeStart` 不回调 | 无法词级高亮 | 降级句级高亮 |
| 前台服务被 OEM 杀 | 后台断播 | 前台服务 + 唤醒锁 + 通知；引导电池白名单，不强制 |
| 通知权限被拒 | 锁屏控制不可用 | 明确提示；允许仅前台听书 |
| Android 14 FGS 限制 | 后台启动失败 | 只在可见 Activity 启动；catch 异常 |
| Activity/Service 双写进度 | 进度错乱 | 单例 `LibraryRepository` + synchronized |
| 内存双份 TextDocument | 低端机 OOM | 共享 `BookSession`，只保留一份 |
| 新增权限破坏“0 权限” | 用户信任 | 明确说明；不申请 INTERNET；权限只用于播放 |

---

## 7. 不做/后续

- **不内置神经 TTS**：v1 用系统 TTS；如果必须完全离线且高音质，再评估 sherpa-onnx/Piper，APK 会增加 50–150MB。
- **不做多角色配音**：需要对话识别、角色聚类、多 voice 调度，复杂度高。
- **不做音频导出**：系统 TTS 不提供音频流。
- **不做 Android Auto/Wear**：MediaSession 已打底，后续可接。
- **不做云同步**：听书进度仍走本地书库。

---

## 8. 一句话方案

> 用系统 TTS 做逐句朗读，`ListenService` 作为唯一播放 owner，前台服务 + MediaSession + 音频焦点 + 唤醒锁保证锁屏可靠；进度与阅读共用 `Book.offset`，句子高亮 + 可选跟随翻页；v1 先做 P0，2–3 周内可交付，不引入网络和第三方 TTS SDK。
